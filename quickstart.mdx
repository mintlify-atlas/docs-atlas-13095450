## What is splat?

splat is an AI-powered debugging tool that combines your compile/runtime errors with contextual code analysis to deliver highly educated debug responses. Perfect for quickly fixing, understanding, and preventing errors.

## Prerequisites

Before you begin, make sure you have:

- Python 3.7 or higher
- pip (Python package manager)
- A [Groq API key](https://groq.com/) for AI inference

## Installation

<Steps>
  <Step title="Install splat">
    Install splat globally using pip:
    
    ```bash
    pip install splat
    ```
    
    Or clone and install from source:
    
    ```bash
    git clone <repository-url>
    cd splat
    pip install -r requirements.txt
    python setup.py install
    ```
  </Step>

  <Step title="Set up your Groq API key">
    Create a `.env` file in your project root and add your Groq API key:
    
    ```bash
    API=your_groq_api_key_here
    ```
    
    <Warning>
      Never commit your `.env` file to version control. splat respects `.gitignore` files automatically.
    </Warning>
  </Step>

  <Step title="Verify installation">
    Check that splat is installed correctly:
    
    ```bash
    splat --version
    ```
  </Step>
</Steps>

## Your First Error Analysis

Let's walk through analyzing a simple Python error with splat.

<Steps>
  <Step title="Create a file with an error">
    Create a file called `example.py` with a syntax error:
    
    ```python example.py
    def greet(name):
        print(f"Hello, {name}"
        # Missing closing parenthesis
    
    greet("World")
    ```
  </Step>

  <Step title="Run splat">
    Use the `splat squash` command with your file's entrypoint:
    
    ```bash
    splat squash "python3 example.py"
    ```
    
    <Info>
      The command format is: `splat squash "<your-normal-run-command>"`
      
      Just like you would normally run your app, pass that same command to splat.
    </Info>
  </Step>

  <Step title="Review the analysis">
    splat will return a structured JSON response with detailed error analysis:
    
    ```json
    {
      "where": {
        "repository_path": "/path/to/your/project",
        "file_name": "example.py",
        "line_number": "2"
      },
      "what": {
        "error_type": "SyntaxError",
        "description": "The opening parenthesis on line 2 was never closed, causing a syntax error"
      },
      "how": {
        "error_origination": "2",
        "suggested_code_solution": "print(f\"Hello, {name}\")"
      }
    }
    ```
  </Step>
</Steps>

## Advanced Usage: Relational Context Analysis

For complex errors involving multiple files and imports, use the `-r` flag to enable relational context analysis.

<Steps>
  <Step title="Understanding relational mode">
    The `-r` flag tells splat to:
    - Analyze all files in the error stack trace
    - Build a dependency graph of related files
    - Include all imported modules and their relationships
    - Provide deeper contextual analysis
    
    <Tip>
      Use `-r` when errors involve imports, module relationships, or cross-file dependencies.
    </Tip>
  </Step>

  <Step title="Create multi-file example">
    Create two related files:
    
    <CodeGroup>
    ```python utils.py
    def calculate_sum(numbers):
        return sum(numbers)
    
    def format_result(value):
        return f"Result: {value}"
    ```
    
    ```python main.py
    from utils import calculate_sum, format_results  # Typo: format_results
    
    numbers = [1, 2, 3, 4, 5]
    result = calculate_sum(numbers)
    print(format_results(result))
    ```
    </CodeGroup>
  </Step>

  <Step title="Run with relational context">
    ```bash
    splat squash -r "python3 main.py"
    ```
    
    splat will:
    1. Detect the ImportError in `main.py`
    2. Analyze the relationship between `main.py` and `utils.py`
    3. Identify that `format_results` should be `format_result`
    4. Provide context from both files in its analysis
  </Step>
</Steps>

## Command Reference

The basic command structure is:

```bash
splat squash <?-r> <entrypoint>
```

<Note>
  **Parameters:**
  - `-r` (optional): Enable relational context analysis for deeper debugging
  - `<entrypoint>`: Your application's run command (e.g., `"python3 app.py"`)
</Note>

### Examples

```bash
# Basic error analysis
splat squash "python3 app.py"

# With relational context
splat squash -r "python3 main.py"

# For scripts with arguments
splat squash "python3 script.py --config config.json"

# For different Python versions
splat squash "python script.py"
```

## How It Works Under the Hood

<Accordion title="Error Capture and Parsing">
  When you run `splat squash`, the tool:
  
  1. Executes your command in a subprocess (`relational.py:15`)
  2. Captures the stderr output containing error tracebacks
  3. Parses the error stack to extract file paths and line numbers (`utils.py:47-74`)
  
  ```python
  # From relational.py
  try:
    subprocess.run(entrypoint, capture_output=True, check=True, text=True)
  except subprocess.CalledProcessError as error:
    traceback: str = error.stderr if error.stderr else str(error)
    error_information: str = str(error)
  ```
</Accordion>

<Accordion title="Dependency Graph Building (with -r flag)">
  When using the `-r` flag, splat builds a comprehensive dependency graph:
  
  1. Parses Python files using AST to extract imports (`utils.py:130-189`)
  2. Builds an adjacency list of file relationships
  3. Recursively traverses the graph to find all related files
  4. Respects `.gitignore` to avoid sensitive files
  
  ```python

  def build_adjacency_list(files: List[str], project_root: str) -> Dict[str, List[str]]:
    # Parses imports using ast.parse()
    # Resolves module paths relative to project root
    # Recursively processes imported files
  ```
</Accordion>

<Accordion title="Context Collection">
  splat uses a repopack-style approach to collect file contents:
  
  - Gathers content from all relevant files
  - Formats them with clear file path headers
  - Creates a comprehensive context string for AI analysis
  
  ```python
  # From utils.py:81-100
  def run_mock_repopack(paths: List[str]) -> str:
    for path in paths:
      with open(path, 'r') as f:
        content = f.read()
      result.append(f"File: {path}\nContent:\n{content}\n")
  ```
</Accordion>

<Accordion title="AI Analysis with Groq">
  splat sends the collected context to Groq's llama3-70b-8192 model:
  
  1. Provides structured system prompts for consistent output (`process.py:14-34`)
  2. Requests JSON-formatted responses with specific fields
  3. Returns actionable debug information including:
     - Error location (file, line number)
     - Error type and description
     - Suggested code fix
  
  ```python
  # From process.py
  chat_completion = client.chat.completions.create(
    messages=[...],
    model="llama3-70b-8192",
    response_format={"type": "json_object"}
  )
  ```
</Accordion>

## Response Structure

Every splat analysis returns a consistent JSON structure:

```json
{
  "where": {
    "repository_path": "<absolute path to repository>",
    "file_name": "<name of file containing error>",
    "line_number": "<line number where error occurred>"
  },
  "what": {
    "error_type": "<specific Python error type>",
    "description": "<concise explanation of error>"
  },
  "how": {
    "error_origination": "<line number where error originated>",
    "suggested_code_solution": "<code snippet to fix the error>"
  }
}
```

## Privacy and Security

<Warning>
  **Your code stays safe:**
  
  - splat respects your `.gitignore` files automatically
  - Sensitive files (credentials, `.env`, etc.) are never analyzed
  - Only error-related files and their dependencies are sent to the AI
</Warning>

<Info>
  splat only analyzes files that are:
  - Part of your project (within the project root)
  - Not excluded by `.gitignore`
  - Directly related to the error (or their dependencies with `-r`)
</Info>

## Best Practices

<Steps>
  <Step title="Use -r for complex errors">
    Enable relational context analysis when:
    - Errors involve multiple files
    - Import/module errors occur
    - The error context isn't clear from a single file
  </Step>

  <Step title="Run from project root">
    Always run splat from your project's root directory for best results.
    
    <Note>
      splat works best with entrypoints that can be launched from the root directory.
    </Note>
  </Step>

  <Step title="Keep your .gitignore updated">
    Ensure your `.gitignore` excludes sensitive files like:
    - `.env` files
    - `credentials.json`
    - API keys and secrets
    - Any proprietary or sensitive data
  </Step>

  <Step title="Use meaningful entrypoints">
    Provide the exact command you use to run your application:
    
    ```bash
    # Good
    splat squash "python3 src/main.py --debug"
    
    # Also good
    splat squash -r "python manage.py runserver"
    ```
  </Step>
</Steps>

## Known Limitations

<Warning>
  Be aware of these current limitations:
  
  - **Formatting**: splat does not conform to project formatting configurations when suggesting code fixes
  - **Sub-modules**: splat may not work well with sub-module entrypoints that don't originate from the root directory
  - **Language support**: Currently optimized for Python (other languages may have limited support)
</Warning>

## Common Error Examples

<Accordion title="Syntax Errors">
  ```python
  # Missing closing parenthesis
  print(f"Hello, {name}"

  # - Error type: SyntaxError
  # - Location: exact line number

  ```
</Accordion>

<Accordion title="Import Errors">
  ```python

  # With -r flag, splat will:
  # - Analyze both the importing and imported files

  # - Suggest the correct import
  ```
</Accordion>

<Accordion title="Name Errors">
  ```python

  # - Identify the undefined variable
  # - Check for similar names in scope
  # - Suggest importing or defining the function
  ```
</Accordion>

<Accordion title="Type Errors">
  ```python

  # - Identify the type mismatch
  ```
